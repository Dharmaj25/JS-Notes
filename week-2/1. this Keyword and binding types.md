# `this` Keyword

---

## What is `this`?

`this` is a keyword that refers to an object.  
Which object? Depends entirely on **how the function is called** — not where it is written.

```
this is decided at CALL TIME.
Not at write time. Not at definition time.
At the moment the function is actually called.
(Exception: arrow functions — fixed at write time)
```

---

## Why `this` Exists

Without `this`, methods are hardcoded to one object:

```js
const user = {
  name: "Alice",
  greet: function() {
    console.log("Hello " + user.name); // hardcoded — breaks if copied
  }
};

const admin = { name: "Bob" };
admin.greet = user.greet;
admin.greet(); // "Hello Alice" ← wrong, still reads user.name
```

With `this`, it's dynamic:

```js
const user = {
  name: "Alice",
  greet: function() {
    console.log("Hello " + this.name); // dynamic
  }
};

const admin = { name: "Bob" };
admin.greet = user.greet;

user.greet();  // "Hello Alice" ✅
admin.greet(); // "Hello Bob"   ✅
```

`this` always refers to whoever is calling the function — not who owns it.

---

## The 4 Rules of `this`

Every `this` question is answered by exactly one of these rules.

```
Priority (high → low):
  Rule 1 → new binding        (highest)
  Rule 2 → Explicit binding   (call, apply, bind)
  Rule 3 → Implicit binding   (object method)
  Rule 4 → Default binding    (lowest)
```

---

## Rule 4 — Default Binding

Applies when a function is called as a **plain standalone function**.  
No object. No `new`. No `call`/`apply`/`bind`.

```js
function show() {
  console.log(this);
}

show(); // window (non-strict) | undefined (strict mode)
```

```js
"use strict";

function show() {
  console.log(this); // undefined
}

show();
```

### The Sneaky Default Binding Trap

A function defined inside a method — but called as a plain function — still gets default binding:

```js
const obj = {
  name: "Alice",
  outer: function() {
    function inner() {
      console.log(this.name); // plain call → default binding
    }
    inner(); // no dot, no new, no call/bind → default
  }
};

obj.outer(); // undefined (strict) | window.name (non-strict)
```

Being physically inside a method doesn't matter.  
What matters is **how** `inner()` is called — and it's called as a plain function.

---

## Rule 3 — Implicit Binding

When a function is called **as a method of an object** (dot notation):  
`this` = the object immediately to the left of the dot.

```js
const user = {
  name: "Alice",
  greet: function() {
    console.log(this.name);
  }
};

user.greet(); // "Alice" — this = user
```

### Nested Objects — Only Immediate Left Matters

```js
const company = {
  name: "Google",
  ceo: {
    name: "Sundar",
    introduce: function() {
      console.log(this.name);
    }
  }
};

company.ceo.introduce(); // "Sundar" — this = ceo (not company)
```

---

### Lost Binding — The Most Common `this` Bug

Extracting a method from an object loses the `this` connection:

```js
const user = {
  name: "Alice",
  greet: function() {
    console.log(this.name);
  }
};

user.greet();          // "Alice" ✅ — implicit binding

const fn = user.greet; // just copying the function reference
fn();                  // undefined ❌ — default binding (no dot)
```

When you extract the function, the context is lost.  
`fn()` is now a plain call — default binding applies.

### Lost Binding in Callbacks

```js
const user = {
  name: "Alice",
  greet: function() {
    console.log(this.name);
  }
};

setTimeout(user.greet, 1000); // undefined ❌
```

`user.greet` is passed as a reference — extracted from `user`.  
`setTimeout` calls it as a plain function. Lost.

**Fix: use `bind`**

```js
setTimeout(user.greet.bind(user), 1000); // "Alice" ✅
```

---

## Rule 2 — Explicit Binding

Manually set `this` using `call`, `apply`, or `bind`.  
Overrides default and implicit binding.

---

### `call` — invoke immediately, args passed individually

```js
function greet(greeting, punctuation) {
  console.log(greeting + " " + this.name + punctuation);
}

const user  = { name: "Alice" };
const admin = { name: "Bob" };

greet.call(user,  "Hello", "!"); // "Hello Alice!"
greet.call(admin, "Hi",    "."); // "Hi Bob."
```

Syntax: `fn.call(thisArg, arg1, arg2, ...)`

---

### `apply` — invoke immediately, args passed as array

```js
greet.apply(user, ["Hello", "!"]); // "Hello Alice!"
```

Syntax: `fn.apply(thisArg, [arg1, arg2, ...])`

```
call  → individual args → fn.call(obj, a, b, c)
apply → array of args   → fn.apply(obj, [a, b, c])
Memory trick: Apply = Array
```

---

### `bind` — does NOT call, returns new function with `this` locked

```js
function greet(greeting) {
  console.log(greeting + " " + this.name);
}

const user = { name: "Alice" };

const greetAlice = greet.bind(user); // returns new function, not called yet

greetAlice("Hello"); // "Hello Alice"
greetAlice("Hi");    // "Hi Alice"
```

`bind` permanently locks `this`. The new function always uses the bound `this`  
no matter how it is called later.

---

### `bind` Cannot Be Overridden — Ever

```js
const user  = { name: "Alice" };
const admin = { name: "Bob" };

const greetAlice = greet.bind(user); // this = user, locked permanently

greetAlice.call(admin);  // "Alice" — call ignored, bind wins
greetAlice.apply(admin); // "Alice" — apply ignored, bind wins
greetAlice.bind(admin)(); // "Alice" — rebind ignored, original bind wins
```

> Once `bind` locks `this`, nothing can change it. This is the only way to permanently freeze `this`.

---

### Partial Application with `bind`

`bind` can also pre-fill arguments:

```js
function intro(city, country) {
  console.log(this.name + " from " + city + ", " + country);
}

const user = { name: "Alice" };

const boundIntro = intro.bind(user, "Jaipur"); // 'this' + first arg pre-filled
boundIntro("India"); // "Alice from Jaipur, India"
```

Arguments passed to `bind` after `thisArg` are pre-filled.  
Remaining args are passed when the bound function is called.  
This is called **partial application** — covered fully in Advanced Functions week.

---

### `call` vs `apply` vs `bind`

```
              call          apply         bind
─────────────────────────────────────────────────
Calls now?    ✅ Yes        ✅ Yes        ❌ No (returns fn)
Args format   Individual   Array         Individual (pre-fill)
Returns       Result        Result        New bound function
Override?     ✅ Yes        ✅ Yes        ❌ No (bind is final)

When to use:
  call  → know args individually, want to call now
  apply → args are already in an array, call now
  bind  → save for later, fix this for callbacks
```

---

## Rule 1 — `new` Binding (Highest Priority)

Calling a function with `new` does 4 things automatically:

```
Step 1 → Creates a brand new empty object {}
Step 2 → Sets 'this' inside the function = that new object
Step 3 → Runs the function body (adds properties to 'this')
Step 4 → Returns 'this' automatically
         (unless the function explicitly returns a different object)
```

```js
function Person(name, age) {
  this.name = name; // this = new empty object
  this.age  = age;
}

const alice = new Person("Alice", 25);

console.log(alice.name); // "Alice"
console.log(alice.age);  // 25
```

### Forgetting `new` — The Dangerous Bug

```js
function Person(name) {
  this.name = name;
}

const alice = Person("Alice"); // forgot new!
// this = window (default binding)
// window.name = "Alice" — global pollution ❌

console.log(alice);       // undefined — nothing returned
console.log(window.name); // "Alice" — leaked to global
```

Without `new`, it's a plain call. Default binding. Properties go on `window`.

## Arrow Functions and `this` — The Exception

Arrow functions are the exception to all 4 rules.

> **Arrow functions do not have their own `this`.**  
> They inherit `this` from the **surrounding lexical scope** — where they were written.  
> This is fixed at write time. It never changes.

---

### Arrow Fixing the Nested Function Problem

```js
// Regular function — broken
const obj = {
  name: "Alice",
  outer: function() {
    function inner() {
      console.log(this.name); // default binding → undefined ❌
    }
    inner();
  }
};
obj.outer(); // undefined

// Arrow function — fixed
const obj = {
  name: "Alice",
  outer: function() {
    const inner = () => {
      console.log(this.name); // lexical this = obj ✅
    };
    inner();
  }
};
obj.outer(); // "Alice"
```

### Arrow Fixing the setTimeout Problem

```js
// Regular function — broken
const user = {
  name: "Alice",
  greet: function() {
    setTimeout(function() {
      console.log(this.name); // undefined ❌ default binding
    }, 100);
  }
};

// Arrow function — fixed
const user = {
  name: "Alice",
  greet: function() {
    setTimeout(() => {
      console.log(this.name); // "Alice" ✅ lexical this = user
    }, 100);
  }
};
```

### Arrow Functions as Object Methods — The Trap

```js
const user = {
  name: "Alice",
  greet: () => {           // arrow as method
    console.log(this.name);
  }
};

user.greet(); // undefined ❌
```

Arrow function is written at the object literal level.  
Object literals do not create a `this` context.  
Arrow looks outward → finds global → `this.name` = undefined.

> **Never use arrow functions as object methods when you need `this` to refer to the object.**

### Arrow Functions Cannot Be Bound

```js
const greet = () => { console.log(this.name); };
const user  = { name: "Alice" };

greet.call(user);   // undefined — ignored
greet.apply(user);  // undefined — ignored
greet.bind(user)(); // undefined — ignored
```

`this` in an arrow is permanently set at write time.  
`call`, `apply`, `bind` have no effect on arrow functions' `this`.

---

## The Priority Decision — Step by Step

When you see `this` in any code, go through this checklist in order:

```
Is it an arrow function?
  YES → this = inherited from surrounding scope at write time
        none of the 4 rules apply. stop here.

Is the function called with 'new'?
  YES → this = the newly created object (Rule 1)

Is the function called with call / apply / bind?
  YES → this = first argument passed (Rule 2)
        if bound with bind → this is locked, cannot be overridden

Is the function called as obj.method()?
  YES → this = obj (object left of the dot) (Rule 3)

None of the above?
  → strict mode   → this = undefined (Rule 4)
  → non-strict    → this = window    (Rule 4)
```

## All Rules Side by Side

```js
function show() { console.log(this.name); }

const user  = { name: "Alice", show };
const admin = { name: "Bob" };

// Rule 4 — Default
show();                    // undefined / window

// Rule 3 — Implicit
user.show();               // "Alice"

// Rule 2 — Explicit (beats implicit)
user.show.call(admin);     // "Bob"
user.show.apply(admin);    // "Bob"
const bound = show.bind(admin);
bound();                   // "Bob"
bound.call(user);          // "Bob" — bind wins, cannot override

// Rule 1 — new
function Person(name) { this.name = name; }
const p = new Person("Charlie");
p.name;                    // "Charlie"
```

**Q14 — call vs apply vs bind with args**
```js
function intro(city, country) {
  console.log(this.name + " from " + city + ", " + country);
}
const user = { name: "Alice" };

intro.call(user, "Jaipur", "India");
intro.apply(user, ["Jaipur", "India"]);

```
<details>
<summary>Answer</summary>

</details>

## What Interviewers Test

**1. All 4 rules in priority order**
Be able to state them and apply them without hesitation.

**2. Lost binding — why and how to fix**
Extracting a method loses `this`. Fix: `bind`. Very common real-world bug.

**3. `bind` cannot be overridden**
Once bound, `call`/`apply`/`bind` again — all ignored. This trips up most candidates.

**4. Arrow functions and `this`**
No own `this`. Inherits lexically. Cannot be bound. Never use as object method.

**5. Default binding inside nested functions**
A plain function call inside a method still gets default binding. Arrow function fixes it.

**6. `call` vs `apply` vs `bind` differences**
`call` and `apply` invoke immediately. `bind` returns a new function. `apply` takes array.  
`bind` is the only permanent one.

---

## Mental Models

**`this` = who is calling right now.**
Not who wrote the function. Not who owns it. Who is calling it at this moment.

**4 rules = 4 questions to ask in order.**
new? → Explicit? → Dot notation? → Plain call?
First yes wins.

**Arrow `this` = frozen at birth.**
Set the moment the arrow function is written. Looks at surrounding scope. Cannot be changed by anyone.

**`bind` = permanent tattoo.**
Once you bind `this`, it's there forever on that function. No removal. No override.
