## Part 1 — Currying

### What is Currying?

Currying is transforming a function that takes multiple arguments into a sequence of functions that each take **one argument at a time**.

```js
// Normal function — all args at once
function add(a, b, c) {
  return a + b + c;
}
add(1, 2, 3); // 6

// Curried version — one arg at a time
function curriedAdd(a) {
  return function(b) {
    return function(c) {
      return a + b + c;
    };
  };
}
curriedAdd(1)(2)(3); // 6
```

Each call returns a new function that waits for the next argument. The function is called step by step.

With arrow functions — much cleaner to read:

```js
const curriedAdd = a => b => c => a + b + c;

curriedAdd(1)(2)(3); // 6
```

Read it right to left: `a` returns a function, that takes `b`, that returns a function, that takes `c`, that returns `a + b + c`.

---

### How Currying Works — Closures Under the Hood

Each returned function is a closure over all the arguments received so far:

```js
const curriedAdd = a => b => c => a + b + c;

const step1 = curriedAdd(1);
// step1 closes over a = 1
// step1 is: b => c => 1 + b + c

const step2 = step1(2);
// step2 closes over a = 1, b = 2
// step2 is: c => 1 + 2 + c

const result = step2(3);
// a = 1, b = 2, c = 3
// 1 + 2 + 3 = 6
```

Every step closes over the previous arguments. They're all alive in memory because each returned function references them.

---

### Why Currying? — The Real Value

The power isn't calling one arg at a time. The power is **creating specialized functions from general ones**:

```js
const multiply = a => b => a * b;

const double = multiply(2);  // specialized — always multiplies by 2
const triple = multiply(3);  // specialized — always multiplies by 3
const tenX   = multiply(10); // specialized — always multiplies by 10

double(5);  // 10
triple(5);  // 15
tenX(5);    // 50

// Use them anywhere
[1, 2, 3].map(double);  // [2, 4, 6]
[1, 2, 3].map(triple);  // [3, 6, 9]
```

`multiply` is general — takes two numbers. `double` and `triple` are specialized — you've pre-decided one argument. Currying lets you go from general to specific.

---

### Auto-Curry — A Generic Curry Function

The above examples are manually curried. A generic `curry` function automatically curries any function:

```js
function curry(fn) {
  return function curried(...args) {
    if (args.length >= fn.length) {
      // received enough args — call the original function
      return fn(...args);
    }
    // not enough args yet — return function waiting for more
    return function(...moreArgs) {
      return curried(...args, ...moreArgs);
    };
  };
}

// Test it
function add(a, b, c) {
  return a + b + c;
}

const curriedAdd = curry(add);

curriedAdd(1, 2, 3); // 6 — all at once
curriedAdd(1)(2)(3); // 6 — one at a time
curriedAdd(1, 2)(3); // 6 — mixed
curriedAdd(1)(2, 3); // 6 — mixed

const add10 = curriedAdd(10);
add10(5, 3); // 18
```

`fn.length` is the number of declared parameters. If you've received that many, call the function. If not, collect more.

> Note: Spread operator (`...args`) is covered in Week 3. For now, understand the concept — the curry function collects arguments across multiple calls and fires when it has enough.

## Part 2 — Partial Application

### What is Partial Application?

Partial application is pre-filling **some** (not necessarily one) arguments of a function, returning a new function that takes the remaining arguments.

```js
function add(a, b, c) {
  return a + b + c;
}

// Partial application — pre-fill a and b
function partial(fn, ...preFilledArgs) {
  return function(...laterArgs) {
    return fn(...preFilledArgs, ...laterArgs);
  };
}

const add10and20 = partial(add, 10, 20);
add10and20(5);  // 35 — 10 + 20 + 5
add10and20(15); // 45 — 10 + 20 + 15
```

---

### Currying vs Partial Application — The Difference

This is one of the most commonly confused pairs in JS interviews.

```
CURRYING:
  → Always produces functions that take ONE argument at a time
  → You always get back a unary function (one param)
  → Transform: f(a, b, c) → f(a)(b)(c)
  → Each step: exactly 1 arg

PARTIAL APPLICATION:
  → Pre-fills ANY number of arguments
  → You can fill 1, 2, or more at once
  → Transform: f(a, b, c) → f(a, b)(c) OR f(a)(b, c)
  → Each step: 1 or more args
```

```js
// Currying — always one at a time
const curriedAdd = a => b => c => a + b + c;
curriedAdd(1)(2)(3); // each call takes exactly 1 arg

// Partial application — any number at a time
const partial = (fn, ...pre) => (...rest) => fn(...pre, ...rest);
const addPartial = partial(add, 1, 2); // pre-fills 2 args at once
addPartial(3); // 6
```

### bind is Partial Application

You already know this from Friday. `bind` does partial application:

```js
function multiply(a, b) {
  return a * b;
}

const double = multiply.bind(null, 2); // pre-fills a = 2
double(5);  // 10
double(10); // 20
```

`bind` with `null` as `thisArg` and pre-filled args = partial application. The distinction: `bind` also locks `this`, while a custom partial function typically doesn't care about `this`.

## Part 3 — Compose

### What is Compose?

Compose takes multiple functions and returns a new function that runs them **right to left**, passing the output of one as the input of the next.

```js
function compose(fn2, fn1) {
  return function(value) {
    return fn2(fn1(value));
  };
}

const double  = n => n * 2;
const addOne  = n => n + 1;

const doubleThenAddOne = compose(addOne, double);
// reads right to left: double first, then addOne

doubleThenAddOne(5); // double(5) = 10, addOne(10) = 11
```

**Right to left** — the rightmost function runs first. This matches mathematical function composition: `f(g(x))` — `g` runs first, then `f`.

### Compose with Multiple Functions

```js
function compose(...fns) {
  return function(value) {
    return fns.reduceRight(function(acc, fn) {
      return fn(acc);
    }, value);
  };
}

const double    = n => n * 2;
const addOne    = n => n + 1;
const square    = n => n * n;

const transform = compose(square, addOne, double);
// right to left: double → addOne → square

transform(3);
// double(3)   = 6
// addOne(6)   = 7
// square(7)   = 49
```

> Note: `reduceRight` is an array method covered in Week 3. For now, understand
> the concept — compose chains functions right to left.

## Part 4 — Pipe

### What is Pipe?

Pipe is exactly like compose but runs functions **left to right** — which feels more natural for most people.

```js
function pipe(fn1, fn2) {
  return function(value) {
    return fn2(fn1(value));
  };
}

const double  = n => n * 2;
const addOne  = n => n + 1;

const doubleThenAddOne = pipe(double, addOne);
// reads left to right: double first, then addOne

doubleThenAddOne(5); // double(5) = 10, addOne(10) = 11
```

Same result as compose — just written in the order that feels natural to read.

### Pipe with Multiple Functions

```js
function pipe(...fns) {
  return function(value) {
    return fns.reduce(function(acc, fn) {
      return fn(acc);
    }, value);
  };
}

const double    = n => n * 2;
const addOne    = n => n + 1;
const square    = n => n * n;

const transform = pipe(double, addOne, square);
// left to right: double → addOne → square

transform(3);
// double(3)   = 6
// addOne(6)   = 7
// square(7)   = 49
```

Same result as the compose example — just written left to right instead of right to left.

> Note: `reduce` is covered in Week 3. For now, understand the concept —
> pipe chains functions left to right, each output becomes the next input.

---

## Compose vs Pipe — The Only Difference

```
COMPOSE:  right to left   →  compose(f, g, h)(x) = f(g(h(x)))
PIPE:     left to right   →  pipe(h, g, f)(x)    = f(g(h(x)))
```

They produce the same result — the functions just appear in reverse order.

```js
const double  = n => n * 2;
const addOne  = n => n + 1;

// These do the same thing:
compose(addOne, double)(5); // double first, addOne second → 11
pipe(double, addOne)(5);    // double first, addOne second → 11
```

Most developers find `pipe` more readable — left to right matches how we think about data flowing through transformations.

## Putting It All Together — A Real Pattern

These patterns combine naturally:

```js
// Curried functions work perfectly with compose/pipe
const multiply = a => b => a * b;
const add      = a => b => a + b;

const double = multiply(2);
const addTen = add(10);
const triple = multiply(3);

const transform = pipe(
  double,   // multiply by 2
  addTen,   // add 10
  triple    // multiply by 3
);

transform(5);
// double(5)  = 10
// addTen(10) = 20
// triple(20) = 60
```

Curried functions are perfect for compose/pipe because they return unary functions — functions that take exactly one argument. And compose/pipe expects functions that take one value and return one value.

## How Everything Connects

```
First-class functions
  → functions are values, can be passed and returned

Closures
  → curried functions close over previously received args
  → partial application closes over pre-filled args
  → compose/pipe close over the array of functions

HOFs
  → curry takes a function, returns a function
  → partial takes a function, returns a function
  → compose/pipe take functions, return a function

bind (Friday)
  → bind is built-in partial application
  → pre-fills this + args, returns new function

All four patterns
  → different ways to create specialized, reusable functions
  → all built on the same foundations
```

**Q15 — Compose vs pipe with same functions reversed**
```js

  return val => fns.reduceRight((acc, fn) => fn(acc), val);

const b = n => n * 2;   // double
const c = n => n - 3;   // subtract 3

console.log(compose(c, b, a)(5)); // c(b(a(5)))
console.log(pipe(a, b, c)(5));    // c(b(a(5)))
console.log(compose(a, b, c)(5)); // a(b(c(5)))
console.log(pipe(c, b, a)(5));    // a(b(c(5)))
```
<details>
<summary>Answer</summary>

`9` — `a(5)=6`, `b(6)=12`, `c(12)=9`. (compose right-to-left: a runs first)
`9` — `a(5)=6`, `b(6)=12`, `c(12)=9`. (pipe left-to-right: a runs first)
`5` — `c(5)=2`, `b(2)=4`, `a(4)=5`. (compose: c runs first)
`5` — `c(5)=2`, `b(2)=4`, `a(4)=5`. (pipe: c runs first)
Compose and pipe produce the same result when functions are in reverse order.
</details>

## What Interviewers Test

**1. Define currying precisely**
Transforming a multi-arg function into a sequence of single-arg functions. NOT the same as partial application. Each step returns a function waiting for exactly one more arg.

**2. Currying vs partial application — know the difference**
Currying: always one arg at a time. Partial application: any number of args pre-filled. `bind` is partial application, not currying.

**3. Why currying is useful**
Creating specialized functions from general ones. Works perfectly with HOFs like map. Makes code more reusable and composable.

**4. Compose vs pipe — direction**
Compose: right to left. Pipe: left to right. Same result when function order is reversed. Most people find pipe more readable.

**5. Implement curry/compose/pipe from scratch**
You will be asked to implement these. Know the logic: curry collects args until it has enough, then calls the function. Compose/pipe chain functions passing output as input.

**6. Connect to closures**
Curried functions work because of closures — each returned function closes over the previously received arguments.

**7. Real use cases**
Redux connect, middleware, data transformation pipelines, reusable validators. Shows you know where these patterns appear in real code.

## Mental Models

**Currying = one thing at a time, every time.**
Like ordering food item by item. You say your order one dish at a time. The restaurant waits until you've ordered everything before cooking.

**Partial application = pre-loading a function.**
Like pre-setting some defaults. You fill in what you know now, leave the rest for later.

**bind = partial application built into JS.**
When you don't care about `this`, `bind(null, arg1)` is just partial application.

**Compose = an assembly line reading right to left.**
Material goes in at the right end, passes through each station, comes out transformed on the left.

**Pipe = an assembly line reading left to right.**
Same factory, same result — just written in the order you'd naturally read it.

**Curried functions + pipe/compose = perfect partners.**
Curried functions are unary — one in, one out. Pipe/compose need exactly that. They fit together naturally.
