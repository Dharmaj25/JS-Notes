# `call` / `apply` / `bind`

---

## Why These Methods Exist

You already know the 4 rules of `this` from Monday.
Rule 2 — Explicit Binding — is what `call`, `apply`, and `bind` implement.

The problem they solve:

```js
function greet() {
  console.log("Hello, " + this.name);
}

const user = { name: "Alice" };
```

`greet` is a standalone function. Called as `greet()`, `this` = `window` (default binding).
But you want `this` to be `user`. That's what explicit binding is for.

```js
greet.call(user); // "Hello, Alice" ✅
```

All three methods — `call`, `apply`, `bind` — let you manually set what `this` should be inside any function. They are methods on `Function.prototype`, so every function in JS has access to them.

---

## `call`

Calls the function **immediately** with a specified `this` and arguments passed **individually**.

```js
function greet(greeting, punctuation) {
  console.log(greeting + " " + this.name + punctuation);
}

const user  = { name: "Alice" };
const admin = { name: "Bob" };

greet.call(user,  "Hello", "!"); // "Hello Alice!"
greet.call(admin, "Hi",    "."); // "Hi Bob."
```

Syntax:
```
fn.call(thisArg, arg1, arg2, arg3, ...)
  ↑       ↑       ↑
  method  what    arguments passed
          this    individually
          becomes
```

`thisArg` = what `this` should be inside the function.
All arguments after `thisArg` are forwarded to the function one by one.

### call with no arguments

```js
function show() {
  console.log(this.name);
}

const user = { name: "Alice" };

show.call(user); // "Alice" — no extra args needed
```

### call with null or undefined as thisArg

```js
function add(a, b) {
  return a + b;
}

add.call(null, 2, 3);      // 5 — this = window (non-strict) / undefined (strict)
add.call(undefined, 2, 3); // 5 — same
```

When you pass `null` or `undefined` as `thisArg`, default binding applies.
Used when you want to call a function with specific args but don't care about `this`.

---

## `apply`

Calls the function **immediately** with a specified `this` and arguments passed as an **array**.

```js
function greet(greeting, punctuation) {
  console.log(greeting + " " + this.name + punctuation);
}

const user = { name: "Alice" };

greet.apply(user, ["Hello", "!"]); // "Hello Alice!"
```

Syntax:
```
fn.apply(thisArg, [arg1, arg2, arg3, ...])
  ↑        ↑       ↑
  method   what    arguments passed
           this    as an ARRAY
           becomes
```

The only difference from `call` is how arguments are passed:
```
call  → fn.call(obj, a, b, c)    individual args
apply → fn.apply(obj, [a, b, c]) array of args
```

Memory trick: **A**pply = **A**rray.

### Real use case for apply — spreading an array into a function

Before the spread operator existed, `apply` was the only way to pass an array as individual args:

```js
const numbers = [3, 1, 4, 1, 5, 9, 2, 6];

// Old way — apply
const max = Math.max.apply(null, numbers); // 9
const min = Math.min.apply(null, numbers); // 1

// Modern way — spread operator (Week 3)
const max = Math.max(...numbers); // 9
```

`Math.max` doesn't accept an array directly — it needs individual arguments. `apply` unpacks the array for you.

In modern JS, the spread operator does this more cleanly. But `apply` still appears in interviews and legacy code.

## `bind`

Does **NOT** call the function. Returns a **new function** with `this` permanently locked to the provided value.

```js
function greet(greeting) {
  console.log(greeting + " " + this.name);
}

const user = { name: "Alice" };

const greetAlice = greet.bind(user); // returns new function — NOT called yet

greetAlice("Hello"); // "Hello Alice" — called later
greetAlice("Hi");    // "Hi Alice"    — still Alice, always Alice
```

Syntax:
```
fn.bind(thisArg, arg1, arg2, ...)
  ↑       ↑       ↑
  method  what    optional: pre-fill
          this    arguments
          becomes
```

`bind` returns a new function. The original function is not changed.

### bind Cannot Be Overridden

Once bound, `this` is permanently frozen. `call`, `apply`, or another `bind` cannot change it:

```js
const user  = { name: "Alice" };
const admin = { name: "Bob" };

function greet() { console.log(this.name); }

const greetAlice = greet.bind(user);

greetAlice();             // "Alice"
greetAlice.call(admin);   // "Alice" — call ignored
greetAlice.apply(admin);  // "Alice" — apply ignored
greetAlice.bind(admin)(); // "Alice" — rebind ignored
```

`bind` is the only permanent explicit binding. Once you bind, nobody can undo it.

### Fixing Lost Binding with bind

You already saw this in Monday's `this` notes. `bind` is the clean fix:

```js
const user = {
  name: "Alice",
  greet: function() {
    console.log(this.name);
  }
};

// Lost binding — setTimeout extracts the function
setTimeout(user.greet, 1000);           // undefined ❌

// Fixed with bind
setTimeout(user.greet.bind(user), 1000); // "Alice" ✅
```

### Partial Application with bind

`bind` can also pre-fill arguments — not just `this`.
Arguments passed to `bind` after `thisArg` are permanently pre-filled:

```js
function multiply(a, b) {
  return a * b;
}

const double = multiply.bind(null, 2); // this = null, a = 2 pre-filled
const triple = multiply.bind(null, 3); // this = null, a = 3 pre-filled

double(5);  // 10 — a=2 (pre-filled), b=5 (passed now)
double(10); // 20 — a=2 (pre-filled), b=10 (passed now)
triple(5);  // 15 — a=3 (pre-filled), b=5 (passed now)
```

`null` as `thisArg` means we don't care about `this` in `multiply` — it doesn't use it.
The first pre-filled arg maps to `a`. Whatever you pass when calling maps to `b`.

Partial application is covered fully on Saturday. `bind` is one way to achieve it.

## call vs apply vs bind — Complete Comparison

```
              call              apply             bind
─────────────────────────────────────────────────────────────────
Calls now?    ✅ Yes            ✅ Yes            ❌ No (returns fn)
Args format   Individual        Array             Individual (pre-fill)
Returns       Result of fn      Result of fn      New bound function
Overridable?  ✅ Yes            ✅ Yes            ❌ No (permanent)

When to use:
  call  → set this + call immediately, know args individually
  apply → set this + call immediately, args already in an array
  bind  → set this for later use, fix this in callbacks,
          partial application
```

## Use Cases — Where Each One Shines

### call — Borrowing methods

The most practical real-world use of `call`:

```js
const user = {
  name: "Alice",
  greet: function() {
    console.log("Hello " + this.name);
  }
};

const admin = { name: "Bob" };

// admin doesn't have greet — borrow it from user
user.greet.call(admin); // "Hello Bob"
```

One object borrows another object's method without copying it.

Another common example — borrowing array methods for array-like objects:

```js
function showArgs() {
  // arguments is array-like but not a real array
  // it doesn't have slice, map etc.
  // borrow slice from Array.prototype using call

  const argsArray = Array.prototype.slice.call(arguments);
  console.log(argsArray);
}

showArgs(1, 2, 3); // [1, 2, 3]
```

> Note: The `arguments` object will be covered properly when we reach Advanced Functions.
> For now, understand the pattern — `call` lets one object use another's method.

### apply — Math operations on arrays

```js
const scores = [85, 92, 78, 96, 88];

const highest = Math.max.apply(null, scores); // 96
const lowest  = Math.min.apply(null, scores); // 78
```

### bind — Event handlers and callbacks

```js
class Timer {
  constructor() {
    this.seconds = 0;
  }

  start() {
    // without bind — this would be lost inside setInterval callback
    setInterval(this.tick.bind(this), 1000);
  }

  tick() {
    this.seconds++;
    console.log(this.seconds);
  }
}

const timer = new Timer();
timer.start(); // 1, 2, 3...
```

### bind — React-style class component pattern

```js
class Button {
  constructor(label) {
    this.label = label;
    this.handleClick = this.handleClick.bind(this); // bound in constructor
  }

  handleClick() {
    console.log(this.label + " clicked");
  }
}

const btn = new Button("Submit");
// now handleClick can be passed anywhere and this is always the button
document.addEventListener("click", btn.handleClick);
```

## Custom `bind` — How It Works Conceptually

Interviewers often ask: *"Can you implement `bind` yourself?"*

This tests whether you truly understand what `bind` does — not just how to use it.

### What bind does, step by step:

```
1. Remember the original function (fn)
2. Remember the thisArg
3. Optionally remember pre-filled args
4. Return a new function that:
   → combines pre-filled args with new args
   → calls the original fn using call with thisArg
   → returns whatever fn returns
```

### Custom bind implementation:

```js
Function.prototype.myBind = function(thisArg) {
  const fn = this; // 'this' here is the function myBind was called on

  // collect any pre-filled args passed to bind
  const preFilled = [];
  for (let i = 1; i < arguments.length; i++) {
    preFilled.push(arguments[i]);
  }

  // return a new function
  return function() {
    // collect args passed when the bound function is called
    const laterArgs = [];
    for (let i = 0; i < arguments.length; i++) {
      laterArgs.push(arguments[i]);
    }

    // combine pre-filled + later args
    const allArgs = preFilled.concat(laterArgs);

    // call original function with locked this and all args
    return fn.call(thisArg, ...allArgs);
  };
};

// Testing it:
function greet(greeting, punctuation) {
  return greeting + " " + this.name + punctuation;
}

const user = { name: "Alice" };
const boundGreet = greet.myBind(user, "Hello");

console.log(boundGreet("!")); // "Hello Alice!"
console.log(boundGreet(".")); // "Hello Alice."
```

> Note: The spread operator (`...allArgs`) is covered in Week 3. For now, understand
> the concept — the pre-filled args and later args are combined and forwarded to the original function.

### The conceptual explanation for interviews:

```
myBind:
  1. Captures the function (this inside myBind)
  2. Captures thisArg and any pre-filled args
  3. Returns a closure that:
     → Takes new args when called later
     → Combines pre-filled + new args
     → Calls original function via call with the locked thisArg
  4. The returned function is a closure over fn, thisArg, preFilled
```

The key insight: `bind` is implemented using `call` internally. And the returned function is a **closure** — it closes over `fn`, `thisArg`, and `preFilled` args from the outer function.

This is where `call`, closures, and first-class functions all come together.

## All Three on the Same Function

```js
function introduce(greeting, role) {
  return greeting + "! I am " + this.name + ", " + role;
}

const person = { name: "Alice" };

// call — immediate, individual args
introduce.call(person, "Hello", "Developer");
// "Hello! I am Alice, Developer"

// apply — immediate, array of args
introduce.apply(person, ["Hello", "Developer"]);
// "Hello! I am Alice, Developer"

// bind — delayed, pre-fill greeting
const aliceIntro = introduce.bind(person, "Hello");
aliceIntro("Designer");
// "Hello! I am Alice, Designer"
aliceIntro("Developer");
// "Hello! I am Alice, Developer"
```

## How Everything Connects

```
this (Monday)
  → 4 rules: new, explicit, implicit, default

Explicit binding (Rule 2)
  → implemented by call, apply, bind

call  → set this + call now + individual args
apply → set this + call now + array of args
bind  → set this permanently + return new function
        uses call internally
        returned function is a closure

Closures (Thursday)
  → bind returns a closure
  → closes over fn, thisArg, pre-filled args

First-class functions (Tuesday)
  → bind returns a function — possible because fns are first-class
  → call and apply take functions and invoke them
```

**Q12 — Custom bind conceptual trace**
```js
Function.prototype.myBind = function(thisArg) {
  const fn = this;
  const preFilled = [];
  for (let i = 1; i < arguments.length; i++) {
    preFilled.push(arguments[i]);
  }
  return function() {
    const laterArgs = [];

      laterArgs.push(arguments[i]);

console.log(boundAdd(3));
console.log(boundAdd(10));
```
<details>
<summary>Answer</summary>

`16` — `this.base(10) + a(1) + b(2) + c(3)` = `16`.
`23` — `this.base(10) + a(1) + b(2) + c(10)` = `23`.
`myBind` pre-fills `a=1, b=2`. `c` is passed at call time. `this` = `obj` (base=10).
</details>

## What Interviewers Test

**1. Explain what each one does — precisely**
`call` → invokes immediately, args individually.
`apply` → invokes immediately, args as array.
`bind` → returns new function, this permanently locked.

**2. bind cannot be overridden — and why**
Once bound, `call`/`apply`/`bind` are all ignored for `this`. This is the most common trick question.

**3. When to use which**
`call` → method borrowing, invoking with known args.
`apply` → when args are already in an array.
`bind` → callbacks, event handlers, fixing lost binding, partial application.

**4. Partial application with bind**
Pre-filling arguments. Know that args after `thisArg` in `bind` are pre-filled. Remaining args passed at call time.

**5. Implement custom bind conceptually**
The key insight: bind uses `call` internally. The returned function is a closure over `fn`, `thisArg`, and pre-filled args. Closures + call + first-class functions all working together.

**6. Difference between call and apply**
Only the argument format differs. `call` = individual. `apply` = array. Memory trick: Apply = Array.

**7. bind vs arrow function for fixing this**
Both fix the `this` problem but differently. `bind` creates a new function with locked `this`. Arrow functions inherit `this` lexically and cannot be changed. For object methods that need `this`, use regular function + `bind`. Arrow functions are better for short callbacks.

## Mental Models

**call = "Call this function right now, pretend this is the object."**
Immediate execution. You hand it `this` and args on the spot.

**apply = "Same as call, but give me the args as a list."**
Identical to `call`. Only difference: pack your args in an array first.

**bind = "Give me a version of this function that always thinks it belongs to this object."**
No immediate call. Returns a new function with a frozen `this`. Use it later, use it anywhere — `this` never changes.

**bind's returned function = a closure.**
It closes over the original function, `thisArg`, and pre-filled args. This is why it works — closures keeping those values alive.

**call vs bind = now vs later.**
`call` is for right now. `bind` is for setting up a function you'll use later — in a callback, event handler, or anywhere `this` might get lost.
