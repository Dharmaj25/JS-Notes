# Functions — Declaration vs Expression, Arrow Functions, Default Params, First-Class Functions

---

## What is a Function?

A function is a reusable block of code — define it once, run it whenever you need it.

```js
function add(a, b) {
  return a + b;
}

add(2, 3);   // 5
add(10, 20); // 30
```

Simple. But how you define that function matters a lot in JavaScript.

---

## Part 1 — Function Declaration

The most basic way to create a function. Starts with the `function` keyword, followed immediately by a name.

```js
function greet(name) {
  return "Hello " + name;
}
```

### The Key Property — Fully Hoisted

Function declarations are **completely** hoisted during the creation phase. The entire function — name and body — is stored in memory before a single line of code runs.

```js
greet("Alice"); // ✅ "Hello Alice" — works before the declaration

function greet(name) {
  return "Hello " + name;
}
```

JS has already stored `greet` in memory during the creation phase. By the time `greet("Alice")` runs, the function already exists.

### What Hoisting Looks Like Under the Hood

```
CREATION PHASE:
  greet → [entire function body stored] ✅

EXECUTION PHASE:
  greet("Alice") → runs fine, greet exists
  function greet() {...} → this line is SKIPPED (already done)
```

## Part 2 — Function Expression

Instead of declaring a standalone named function, you assign a function to a variable.

```js
const greet = function(name) {
  return "Hello " + name;
};
```

The function itself has no name — it's **anonymous**. It lives inside the variable `greet`.

### Named Function Expression

You can optionally give it a name:

```js
const greet = function sayHello(name) {
  return "Hello " + name;
};
```

`sayHello` is only accessible **inside** the function body — NOT outside.

```js
greet("Alice");    // ✅ works
sayHello("Alice"); // ❌ ReferenceError — not accessible outside
```

**When is a named function expression useful?**

Recursion inside the function — the function can reference itself by name:

```js
const factorial = function calculate(n) {
  if (n <= 1) return 1;
  return n * calculate(n - 1); // ✅ references itself by name
};

factorial(5); // 120
calculate(5); // ❌ ReferenceError — not accessible outside
```

Also useful for debugging — the function name shows up in stack traces instead of "anonymous".

### Hoisting Behavior — Follows the Variable

Function expressions do NOT get their body hoisted. They follow the hoisting rules of whatever keyword declares them.

```js
// With const/let → TDZ
greet("Alice"); // ❌ ReferenceError: Cannot access 'greet' before initialization
const greet = function(name) { return "Hello " + name; };

// With var → undefined
greet("Alice"); // ❌ TypeError: greet is not a function
                // var greet is hoisted as undefined
                // calling undefined() = TypeError
var greet = function(name) { return "Hello " + name; };
```

```
CREATION PHASE (with var):
  greet → undefined   ← only the var is hoisted, not the function

EXECUTION PHASE:
  greet("Alice") → calling undefined() → TypeError ❌
  greet = function(){...} → function assigned here, too late
```

## Declaration vs Expression — Complete Comparison

```
                    DECLARATION               EXPRESSION
───────────────────────────────────────────────────────────────────
Syntax              function foo() {}         const foo = function() {}
Hoisted?            ✅ Fully (name + body)    ⚠️ var → undefined
                                              ❌ let/const → TDZ
Callable before?    ✅ Yes                    ❌ No
Has a name?         ✅ Always                 Optional (can be anonymous)
Use as argument?    Awkward                   ✅ Natural
Return from fn?     Awkward                   ✅ Natural
Conditional assign? ❌ Inconsistent           ✅ Clean
```

### When to Use Expression Over Declaration

**1. Passing as an argument:**
```js
[1, 2, 3].map(function(n) { return n * 2; }); // natural
```

**2. Returning from a function:**
```js
function makeMultiplier(x) {
  return function(y) {
    return x * y;
  };
}

const double = makeMultiplier(2);
double(5); // 10
```

**3. Conditional assignment:**
```js
let greet;

if (language === "hindi") {
  greet = function() { return "Namaste"; };
} else {
  greet = function() { return "Hello"; };
}
```

You can't do this cleanly with function declarations.

## Part 3 — Arrow Functions

Introduced in ES6. A shorter, cleaner syntax for writing functions.

```js
// Regular function expression
const add = function(a, b) { return a + b; };

// Arrow function — same thing
const add = (a, b) => { return a + b; };

// Arrow — implicit return (single expression, drop braces + return)
const add = (a, b) => a + b;
```

### All Arrow Function Syntax Forms

```js
// Zero parameters — keep ()
const greet = () => "Hello";

// One parameter — can drop ()
const double = n => n * 2;

// Multiple parameters — keep ()
const add = (a, b) => a + b;

// Multi-line body — need {} and explicit return
const add = (a, b) => {
  const result = a + b;
  return result;
};

// Returning an object literal — wrap in ()
// Without () → JS thinks {} is the function body → returns undefined
const getUser = () => ({ name: "Alice", age: 25 }); // ✅
const getUser = () => { name: "Alice" };             // ❌ returns undefined
```

## Part 4 — Arrow Functions and `this` — Lexical `this`

This is the most important thing about arrow functions. You already know `this` deeply from Monday — this is where it all connects.

### The Problem Arrow Functions Solve

```js
// Regular function in setTimeout — BROKEN
const user = {
  name: "Alice",
  greet: function() {
    setTimeout(function() {
      console.log(this.name); // undefined ❌
      // setTimeout calls this as a plain function
      // default binding → this = window
    }, 1000);
  }
};

// Arrow function in setTimeout — FIXED
const user = {
  name: "Alice",
  greet: function() {
    setTimeout(() => {
      console.log(this.name); // "Alice" ✅
      // arrow has no own this
      // inherits from greet's context = user
    }, 1000);
  }
};
```

### The Rule

> **Regular functions have their own `this` — decided at call time.**
> **Arrow functions have NO own `this` — they inherit `this` from where they are written.**

```
Regular function this → decided at CALL TIME
Arrow function this  → decided at WRITE TIME (lexical)
                       inherited from surrounding scope
                       NEVER changes
```

### Arrow `this` Cannot Be Changed

`call`, `apply`, `bind` are completely ignored for an arrow function's `this`:

```js
const greet = () => { console.log(this.name); };
const user  = { name: "Alice" };

greet.call(user);   // undefined — call ignored
greet.apply(user);  // undefined — apply ignored
greet.bind(user)(); // undefined — bind ignored
```

The `this` of an arrow function is permanently set where it is written. Nobody can change it.

### When NOT to Use Arrow Functions

**Case 1: As object methods — `this` will NOT refer to the object**

```js
const user = {
  name: "Alice",
  greet: () => {
    console.log(this.name); // undefined ❌
    // arrow written at object literal level
    // object literals don't create a 'this' context
    // arrow looks outward → global → undefined
  }
};

user.greet(); // undefined ❌
```

Use a regular function instead:

```js
const user = {
  name: "Alice",
  greet: function() {
    console.log(this.name); // "Alice" ✅
  }
};
```

**Case 2: As constructors — cannot use `new`**

```js
const Person = (name) => {
  this.name = name;
};

new Person("Alice"); // ❌ TypeError: Person is not a constructor
// Arrow functions have no prototype and no own this
// Cannot be used with new
```

### Arrow Function Limitations — Complete List

```
❌ No own 'this'            → inherits lexically from surrounding scope
❌ Cannot use 'new'         → not a constructor, no prototype
❌ No 'prototype' property  → no prototype chain
❌ Cannot be a generator    → no function* arrow syntax
❌ 'this' cannot be changed → call/apply/bind ignored for this
```

> Note: Arrow functions also have no `arguments` object.
> The `arguments` object and rest parameters are covered in a later topic.

## Part 5 — Default Parameters

### The Problem Before ES6

Handling missing arguments used to require manual checks with `||`:

```js
function greet(name) {
  name = name || "Guest"; // old way
  return "Hello " + name;
}
```

The problem: `||` falls back on ANY falsy value — not just missing values:

```js
function multiply(a, b) {
  b = b || 1;
  return a * b;
}

multiply(5, 0); // 5 ← WRONG. 0 is falsy, b becomes 1 instead of 0
```

### ES6 Default Parameters

```js
function greet(name = "Guest") {
  return "Hello " + name;
}

greet("Alice");    // "Hello Alice"
greet();           // "Hello Guest" — undefined triggers default
greet(undefined);  // "Hello Guest" — undefined triggers default
greet(null);       // "Hello null"  — null does NOT trigger default
greet("");         // "Hello "      — empty string does NOT trigger default
greet(0);          // "Hello 0"     — 0 does NOT trigger default
greet(false);      // "Hello false" — false does NOT trigger default
```

> **Only `undefined` triggers a default parameter.**
> All other falsy values — `null`, `0`, `""`, `false`, `NaN` — do NOT.

This fixes the `||` problem:

```js
function multiply(a, b = 1) {
  return a * b;
}

multiply(5, 0); // 0 ✅ — 0 doesn't trigger default, b stays 0
multiply(5);    // 5 ✅ — no b → undefined → default 1 applied
```

### Default Can Be Any Expression

```js
// A function call as a default — lazily evaluated
function getDefault() { return 42; }

function foo(x = getDefault()) {
  return x;
}

foo();   // 42 — getDefault() is called
foo(10); // 10 — getDefault() is never called
```

Default expressions are **lazily evaluated** — only computed when the parameter is actually needed (when `undefined` is received). If you pass a value, the default expression never runs.

### Default Can Reference Earlier Parameters

```js
function multiply(a, b = a) {
  return a * b;
}

multiply(5);    // 25 — b defaults to a (5)
multiply(5, 2); // 10 — b is 2, default ignored
```

**But NOT later parameters — TDZ applies:**

```js
function foo(a = b, b = 2) {
  return a + b;
}

foo(); // ❌ ReferenceError
       // Parameters evaluated left to right
       // When 'a = b' runs, b is still in TDZ
```

You already know this from Week 1 — TDZ. Parameters work the same way. Left to right. `b` hasn't been initialized yet when `a = b` tries to read it.

### Default Parameters With Expressions That Have Side Effects

```js
let count = 0;

function increment(val = ++count) {
  return val;
}

increment();   // 1 — no val passed, default runs, count = 1
increment();   // 2 — no val passed, default runs, count = 2
increment(10); // 10 — val passed, default never runs, count stays 2
increment();   // 3 — no val passed, default runs, count = 3
```

The default expression runs fresh each time it's needed — not once at definition time.

## Part 6 — First-Class Functions

In JavaScript, functions are **first-class citizens**.

This means functions are treated exactly like any other value — a number, a string, an object.

> If something is "first-class", it means you can do with it everything you do with any other value: assign it, pass it, return it, store it.

### What First-Class Means in Practice

**1. Assign to a variable:**
```js
const greet = function() { return "Hello"; };
const sayHi = greet; // functions are values, just like numbers
sayHi(); // "Hello"
```

**2. Pass as an argument to another function:**
```js
function runTwice(fn) {
  fn();
  fn();
}

runTwice(function() {
  console.log("running");
});
// "running"
// "running"
```

**3. Return from a function:**
```js
function makeGreeter(greeting) {
  return function(name) {
    return greeting + " " + name;
  };
}

const hello = makeGreeter("Hello");
hello("Alice"); // "Hello Alice"
hello("Bob");   // "Hello Bob"
```

**4. Store in data structures:**
```js
const actions = {
  greet: function() { return "Hello"; },
  farewell: function() { return "Goodbye"; }
};

const handlers = [
  function() { console.log("first"); },
  function() { console.log("second"); }
];

handlers[0]();   // "first"
actions.greet(); // "Hello"
```

**5. Have properties and methods:**

Functions are objects in JS. They have built-in properties:

```js
function greet(name, age) {
  return "Hello " + name;
}

console.log(greet.name);   // "greet" — function's name
console.log(greet.length); // 2 — number of declared parameters
console.log(typeof greet); // "function"
```

## Part 7 — Higher-Order Functions

A **higher-order function** is any function that:
- Takes a function as an argument, **OR**
- Returns a function, **OR**
- Both

This is ONLY possible because functions are first-class citizens.

```js
// Takes a function → higher order
function runTwice(fn) {
  fn();
  fn();
}

// Returns a function → higher order
function multiplier(x) {
  return function(y) {
    return x * y;
  };
}

const triple = multiplier(3);
triple(5); // 15

// Both → higher order
function pipe(fn1, fn2) {
  return function(value) {
    return fn2(fn1(value));
  };
}

const doubleThenAddOne = pipe(
  n => n * 2,
  n => n + 1
);

doubleThenAddOne(5); // 11 — (5 * 2) + 1
```

Built-in higher-order functions you use every day:

```js
[1, 2, 3].map(n => n * 2);                  // map takes a function
[1, 2, 3].filter(n => n > 1);               // filter takes a function
[1, 2, 3].reduce((acc, n) => acc + n, 0);   // reduce takes a function
setTimeout(fn, 1000);                        // setTimeout takes a function
```

> These built-in HOFs will be covered deeply in Week 3 (Array Methods day).
> For now, just recognize the pattern — they all take functions as arguments.

## How Everything Connects

```
Declaration vs Expression
  → Hoisting behavior is the key difference
  → Expressions are more flexible — pass, return, assign conditionally

Arrow Functions
  → Shorter syntax
  → No own 'this' — inherits lexically (solves the callback this problem)
  → Cannot be constructors, no prototype

Default Parameters
  → Only undefined triggers the default (not null, 0, "", false)
  → Can reference earlier params, not later ones (TDZ)
  → Lazy evaluation — only computed when actually needed

First-Class Functions
  → Functions are values — assign, pass, return, store
  → This enables Higher-Order Functions
  → HOF enables callbacks, closures, currying, composition
  → Everything advanced in JS builds on this foundation
```

**Q4 — Default parameter: only undefined triggers**
```js
function multiply(a, b = 2) {
  return a * b;
}

console.log(multiply(5));
console.log(multiply(5, 0));
console.log(multiply(5, null));
console.log(multiply(5, undefined));
console.log(multiply(5, false));
```
<details>
<summary>Answer</summary>

`10` — `b` defaults to `2`. No b passed = undefined = default triggered.
`0` — `0` does NOT trigger default. `5 * 0 = 0`.
`0` — `null` does NOT trigger default. `null` coerces to `0` in multiplication. `5 * 0 = 0`.
`10` — `undefined` DOES trigger default. `b = 2`. `5 * 2 = 10`.
`0` — `false` does NOT trigger default. `false` coerces to `0`. `5 * 0 = 0`.
</details>

**Q5 — Arrow lexical this inside method**

<details>
<summary>Answer</summary>

`"Alice"`. Arrow inherits `this` from `greet`. `greet`'s `this` = `user` (implicit binding). Arrow uses that lexically — even though `helper()` is called as a plain function, arrow doesn't care about how it's called.
</details>

</details>

## What Interviewers Test

**1. Hoisting difference — declaration vs expression**
Declaration → fully hoisted. Expression with `var` → `undefined` (TypeError when called). Expression with `const`/`let` → TDZ (ReferenceError). Know the exact error for each.

**2. Arrow function `this` — lexical, not dynamic**
Arrow has no own `this`. Inherits from where written. Cannot be changed with `call`/`apply`/`bind`. Never use as object method. Connects directly to Monday's `this` topic.

**3. Only `undefined` triggers defaults**
`null`, `0`, `""`, `false` — none trigger default params. Only `undefined` does. Common output question trap.

**4. Arrow limitations**
No own `this`, cannot use `new`, no `prototype`. Know all of them cold.

**5. Functions are first-class values**
Can be assigned, passed, returned, stored in objects/arrays. This enables everything advanced.

**6. Named function expression scope**
The name is only accessible inside the function body — not outside. Used for recursion and stack traces.

**7. Default parameter lazy evaluation**
Defaults are only computed when `undefined` is received. Side-effect expressions in defaults run only when triggered.

**8. Default parameter TDZ**
Parameters evaluated left to right. A later parameter is in TDZ when an earlier one tries to reference it.

## Mental Models

**Declaration = announced to the whole room before the meeting starts.**
Fully hoisted. Available anywhere in its scope — even before the line it's written on.

**Expression = hired at the door after the meeting already started.**
Only available after the assignment line runs. Before that — `undefined` (var) or locked in TDZ (let/const).

**Arrow function = borrower, not owner.**
Borrows `this` from whoever surrounds it at write time. Owns nothing — no `this`, no `prototype`. Cannot be called as constructor.

**Default parameter = fallback only for the absent.**
Show up with `undefined` (absent) → get the default. Show up with `null`, `0`, or `false` (present but falsy) → keep what you brought.

**First-class function = function is just a value.**
Like a number. Like a string. Put it in a box, hand it to someone, get one back, store a bunch of them — all valid.

**Higher-order function = a function that works with other functions.**
Takes one in, or gives one out, or both. Built entirely on the fact that functions are first-class.
